# 벡터 DB 연구실 — 표에 담기지 않는 말을 저장하는 법 (vector_db_lab)

> 영화 별점은 표에 넣으면 되는데, 리뷰와 SNS 글의 "뜻"은 어디에 어떻게 저장해야 찾을 수 있을까?

조수 하루가 처음으로 인턴 교육을 맡았습니다. 하루는 긴장한 채 인턴 시아·모아에게 질문을 던지며 수업을 이끌고, 막히면 초파리 연구원과 주판봇이 실험으로 돕고, 단계마다 박사가 정리합니다. 방청석의 X1~X3는 떨리는 하루를 걱정하며 지켜봅니다.
관계형 DB(표·SQL)의 한계와 자연어 데이터의 특징에서 출발해, 임베딩 → 벡터 DB 색인 → LLM과 RAG → 현장 사례까지 다섯 장, 특강 두 장(어텐션·트랜스포머 3D, 코사인 실전·지식 그래프·온톨로지), 실전 연습장으로 갑니다. 모든 장에 직접 움직이는 실험 도구(동적 대시보드, 6·7장은 3D 포함)가 4~5개씩 있습니다.

## 데이터와 숫자 표시 원칙

- **모든 데이터는 가상입니다.** 영화 8편, 리뷰 483개, SNS 글 139개, 가상 OTT 「랩플릭스」 안내 문서 12개와 질문 16개를 `code/make_data.py`가 만듭니다. 리뷰마다 "무엇을 좋다·나쁘다고 했나" 이름표가 있어 검색을 채점합니다.
- **교육용 임베딩:** 사람이 뜻을 정한 289개 낱말, 24차원(차원마다 "재미", "감동" 같은 이름) — `code/lexicon.py`. 실제 임베딩 모델(384~1,536차원, 이름 없음)의 원리를 눈으로 보이게 만든 설명용입니다. 부정어("안", "~지 않")는 바로 옆 낱말의 "좋고 나쁨"을 뒤집습니다. 이 사전은 이 연구실 데이터의 말투를 알고 만든 것이라, 좌표 검색 점수는 실제 모델이 처음 보는 데이터를 찾을 때보다 후할 수 있습니다(설명용 비교).
- 페이지 안 모든 실험은 `build/vlab.js`로 브라우저에서 직접 계산하고, 같은 계산을 `code/analysis.js`가 `data/results.json`에 남깁니다(본문 숫자의 원본).
- 4·5장에서 **LLM이 문장을 쓰는 부분은 미리 적어 둔 답으로 흉내** 냅니다. 찾기·점수·정답 판정은 실제 계산입니다.
- 6장의 **어텐션은 교육용 좌표로 흉내 낸 설명용**입니다(Q = K = V, Q 변환·세 머리 규칙·다음 말의 사전 확률은 사람이 정한 가정). 벡터 DB 검색(모델 밖)과 어텐션(모델 안)은 다른 곳에서 일어난다는 점을 짚습니다.
- 7장의 지식 그래프(점 45개·사실 37개)와 온톨로지(클래스 37개)는 랩플릭스 안내 문서에서 사람이 뽑은 설명용입니다(`code/make_graph.py`).
- 3장의 점 5,000개는 설명용 2차원 점 구름이고, 그래프 색인은 HNSW를 두 층으로 줄인 설명용 구현입니다.
- 숫자는 교육용 예시이며 실제 서비스 운영·투자 권고가 아닙니다.
