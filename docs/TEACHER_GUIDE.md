## 1장 · 표에 담기지 않는 말

**학습 목표**

- 관계형 DB가 정형 데이터에 강한 이유를 말할 수 있다
- LIKE 검색의 정밀도·재현율을 계산하고 해석할 수 있다
- 자연어 데이터의 특징 9가지를 예로 설명할 수 있다

**시연 순서 팁** 1-2 LIKE 검색기에서 "놓친 리뷰 보기"를 켜는 장면이 수업의 전환점입니다. "찾은 것"보다 "놓친 것"을 세게 합니다.

**토론 질문** 여러분 회사에서 LIKE(또는 Ctrl+F)로 찾다가 놓친 경험은? 그때 무엇을 놓쳤나요?

**퀴즈 정답**

- q11-1. 관계형 DB와 SQL이 가장 잘하는 일은? → **영화별 평균 별점 정확히 내기** — 별점은 정해진 항목의 숫자라서 평균·조건 검색이 정확합니다.
- q11-2. 벡터 DB를 쓰면 별점·날짜를 담은 표는 어떻게 되나? → **그대로 두고 문장의 뜻만 좌표로 따로 저장한다** — 정형 정보는 표가 계속 맡고, 벡터는 문장의 뜻을 맡습니다. 실제 서비스는 둘을 함께 씁니다.
- q12-1. LIKE로 찾은 17개 중 14개가 맞았고, 정답은 모두 121개다. 재현율은? → **약 12%** — 재현율 = 맞게 찾은 수 ÷ 정답 전체 = 14 ÷ 121 ≈ 11.6%. 정밀도(14 ÷ 17 ≈ 82%)와 헷갈리기 쉽습니다.
- q12-2. "안 재밌어요"가 LIKE '%재밌%'에 걸리는 이유는? → **LIKE는 글자 모양만 보기 때문** — "재밌"이라는 글자가 들어 있으니 걸립니다. 앞의 "안"이 뜻을 뒤집는다는 것은 모릅니다.
- q13-1. 첫 주 글로 만든 태그 규칙이 둘째 주에 흔들린 가장 큰 이유는? → **처음 보는 이야기와 새 말투가 들어와서** — 규칙은 사람이 미리 생각한 낱말만 잡습니다. 결제 오류 이야기와 DM 광고는 규칙에 없었습니다.
- q13-2. 동의어 사전 LIKE의 F1이 꽤 높은데도 한계로 꼽히는 것은? → **사람이 계속 만들고 고쳐야 한다** — 잘 만든 사전은 정확하지만, 말이 바뀔 때마다 사람이 손봐야 합니다.
- q14-1. "꿀잼"과 "시간 가는 줄 몰랐다"처럼 글자는 안 겹치는데 뜻이 같은 경우는 어떤 특징인가? → **같은 뜻 다른 표현** — 같은 뜻을 다른 모양으로 말하는 경우입니다. 글자 일치 검색이 가장 크게 놓치는 자리입니다.
- q14-2. "배우가 아깝다"가 "돈 아깝다" 검색에 섞여 들어오는 문제는? → **다의어(같은 모양, 다른 뜻)** — "아깝다"라는 같은 모양이 다른 뜻(배우 칭찬 + 영화 아쉬움)으로 쓰였습니다.

## 2장 · 말을 좌표로

**학습 목표**

- 낱말 세기와 임베딩의 차이를 설명할 수 있다
- 코사인·유클리드·내적의 범위와 쓰임을 비교할 수 있다
- 정규화가 왜 필요한지 말할 수 있다

**시연 순서 팁** 2-2 임베딩 해부실에서 "돈이 하나도 안 아깝다"를 넣어 빨간 물결(부정어)을 보여 주고, 2-3 화살표에서 B의 길이만 늘려 내적이 커지는 것을 보여 줍니다.

**토론 질문** "꿀잼"과 "노잼"은 가까울까, 멀까? 실제 임베딩 모델에서는 어떨지 토론해 보세요.

**퀴즈 정답**

- q21-1. 낱말 세기로 "꿀잼"과 "재밌어요"의 닮음이 0인 이유는? → **두 낱말이 서로 다른 자리를 써서** — 낱말마다 자리가 따로라, 겹친 자리가 없으면 닮음이 0입니다. 뜻이 같다는 관계를 담을 곳이 없습니다.
- q21-2. "꿀잼 강추"와 "재밌어요 강추"의 낱말 세기 닮음은? → **0.5** — 겹친 낱말 "강추" 1개 ÷ (√2 × √2) = 0.5. 뜻이 아니라 "강추"가 같아서 생긴 닮음입니다.
- q22-1. 임베딩에서 "꿀잼"과 "노잼"은 어떻게 놓이나? → **같은 주제(재미) 쪽, 좋고 나쁨만 반대** — 둘 다 "재미" 성분이 크고 "좋고 나쁨"만 부호가 다릅니다. 주제가 같아서 생각보다 가깝다는 점이 실제 임베딩의 흔한 함정입니다.
- q22-2. 실제 임베딩 모델과 이 연구실 교육용 임베딩의 가장 큰 차이는? → **실제 모델은 성분에 이름이 없고 데이터에서 스스로 배운다** — 교육용은 사람이 성분 이름과 값을 정했습니다. 실제 모델은 수백~수천 개 성분을 수많은 문장에서 학습합니다.
- q23-1. q = (0.8, 0.6), x = (0.6, 0.8)의 코사인은? → **0.96** — 내적 0.48 + 0.48 = 0.96, 두 길이가 1이므로 코사인 0.96.
- q23-2. 모든 벡터를 길이 1로 맞추면? → **코사인과 내적이 같은 순위를 낸다** — 길이가 1이면 내적 = 코사인이고, 유클리드 거리도 코사인과 같은 순서가 됩니다.
- q24-1. 의미 검색에서 질문 문장은 어떻게 다루나? → **리뷰와 같은 임베딩으로 좌표를 만든다** — 질문도 같은 방식으로 좌표로 바꿔야 리뷰 좌표와 거리를 잴 수 있습니다.
- q24-2. 별점 1점인데 "감동" 검색 상위에 나온 리뷰를 걸러 내려면? → **별점 같은 표 정보로 함께 거른다** — 비꼬는 말은 좌표만으로 잘 안 잡힙니다. 별점 같은 정형 정보(메타데이터)로 함께 거르면 됩니다.

## 3장 · 벡터 창고

**학습 목표**

- 저장 용량을 어림할 수 있다
- 근사 검색의 속도·재현율 맞바꿈을 설명할 수 있다
- 메타데이터 필터의 먼저/나중 거르기 차이를 말할 수 있다

**시연 순서 팁** 3-2에서 처음 질문 자리는 서랍 1개로 놓치는 자리로 정해져 있습니다. nprobe를 1→4로 올리며 초록 고리가 채워지는 것을 보여 줍니다.

**토론 질문** 우리 서비스라면 재현율 몇 %를 바닥으로 정할까? 그 이유는?

**퀴즈 정답**

- q31-1. 리뷰 100만 개 × 768차원 × 4바이트는 대략? → **약 3GB** — 1,000,000 × 768 × 4 = 3,072,000,000바이트 ≈ 3.07GB.
- q31-2. 벡터 DB 레코드에서 메타데이터의 역할은? → **장르·별점 같은 사실로 결과를 거른다** — 메타데이터는 좌표가 모르는 사실을 담아 거르기에 씁니다.
- q32-1. 서랍 색인(IVF)에서 nprobe를 늘리면? → **느려지고 정확해진다** — 서랍을 더 열수록 비교가 늘어 느려지고, 놓치는 정답이 줄어듭니다.
- q32-2. N=5,000, 서랍 64개, nprobe 4일 때 비교 횟수 어림값은? → **약 376번** — 64 + (5,000 ÷ 64) × 4 ≈ 64 + 312 = 376.
- q33-1. HNSW 위층(고속도로)의 역할은? → **먼 거리를 몇 번 만에 건너 질문 근처로 데려간다** — 위층은 듬성듬성한 지름길이라 몇 번만 건너도 질문 근처에 닿습니다.
- q33-2. HNSW의 약점으로 맞는 것은? → **연결선 저장에 메모리가 많이 든다** — 점마다 이웃 연결을 저장하므로 메모리가 들고, 지우기·대량 추가 때 다시 잇는 비용이 있습니다.
- q34-1. "찾은 뒤 거르기"에서 결과가 k개보다 적게 나오는 이유는? → **먼저 찾은 k개 중에 조건에 맞는 것이 적어서** — 먼저 찾은 몇 개 안에서만 거르기 때문에, 조건이 까다로우면 모자랍니다.
- q34-2. 비꼬는 리뷰(별점 1점, "감동이다 ^^")를 걸러 내는 데 도움이 되는 것은? → **별점 메타데이터 조건** — 별점 같은 사실 정보로 함께 거르면 뜻과 별점이 엇갈린 리뷰를 걸러 낼 수 있습니다.
- q35-1. 결제 기록 저장에 알맞은 곳은? → **관계형 DB** — 결제는 한 건도 틀리면 안 되어 트랜잭션(ACID)이 필요합니다. 관계형 DB의 강점입니다.
- q35-2. pgvector는 무엇인가? → **PostgreSQL에 벡터 열과 벡터 색인을 더하는 확장** — 이미 쓰는 PostgreSQL에서 벡터 검색을 함께 할 수 있게 해 주는 확장입니다.

## 4장 · 찾아서 답하는 AI

**학습 목표**

- LLM의 환각이 왜 생기는지 설명할 수 있다
- RAG 여섯 걸음을 순서대로 말할 수 있다
- 조각 크기·k·α·문턱·날짜 필터의 효과를 말할 수 있다

**시연 순서 팁** 4-2 시뮬레이터에서 "랩플릭스 회사 주가는 얼마야?"를 눌러 엉뚱한 근거가 문턱을 넘는 장면을 보여 줍니다. 4-4에서는 LP-204 질문으로 α를 1→0.3으로 내립니다.

**토론 질문** 사내 규정 챗봇을 만든다면 구버전 문서를 어떻게 관리할까?

**퀴즈 정답**

- q41-1. LLM이 가상 회사 랩플릭스의 요금을 틀리게 답한 가장 큰 이유는? → **배운 글에 그 정보가 없는데도 그럴듯한 말을 이어서** — LLM은 자주 나온 말을 잇습니다. 배운 글에 없는 사내 정보는 모르고, 모를 때도 그럴듯한 숫자를 지어냅니다.
- q41-2. "연기" 뒤에 온 말 29번 중 "차력쇼"가 17번이면 P(차력쇼 | 연기)는? → **약 59%** — 17 ÷ 29 ≈ 0.586, 약 59%.
- q42-1. RAG에서 "근거 문턱"을 너무 낮추면? → **엉뚱한 조각을 근거로 답을 지어낸다** — 점수가 낮은 엉뚱한 조각도 통과해 LLM에게 넘어갑니다(주가 질문).
- q42-2. 프롬프트에 찾은 조각의 제목·날짜를 함께 넣는 이유는? → **답에 출처를 달아 사람이 확인할 수 있게** — 출처가 있어야 답이 어디서 왔는지 확인하고, 틀린 근거를 걸러 낼 수 있습니다.
- q43-1. 조각을 너무 잘게 자를 때의 위험은? → **답에 필요한 앞뒤 문장이 다른 조각으로 갈라진다** — "3일 이내"와 "재생하지 않았다면"이 갈라지면 한 조각만으로는 답이 불완전합니다.
- q43-2. k = 3, 조각 200자면 LLM에게 넘기는 글은 대략? → **약 600자** — 3 × 200 = 600자 안팎. 문장 단위로 끊어 조금 달라집니다.
- q44-1. "LP-204"처럼 코드가 든 질문에 하이브리드 검색이 유리한 이유는? → **글자 점수가 코드를 정확히 맞추기 때문** — 임베딩은 LP-204와 LP-503을 모두 "오류"로 읽지만, 글자 점수는 "LP-204" 글자 그대로를 잡습니다.
- q44-2. α = 1이면? → **뜻 점수만 쓴다** — 섞은 점수 = α × 뜻 + (1 − α) × 글자. α = 1이면 뜻 점수만 남습니다.
- q45-1. 옛 환불 규정 문서가 함께 찾아지는 문제를 막는 기본 방법은? → **작성일·폐기 여부 메타데이터로 최신 판만 거른다** — 감사 등으로 지우지 못하는 경우가 많아, 메타데이터로 거르는 것이 기본입니다.
- q45-2. 사내 기밀 문서를 RAG에 넣을 때 함께 걸어야 할 조건은? → **질문한 사람의 열람 권한** — 권한이 없는 사람에게 기밀 조각이 답으로 나가지 않도록 권한 정보를 메타데이터로 겁니다.

## 5장 · 현장 사례

**학습 목표**

- 별점(표)과 리뷰 좌표(벡터)를 함께 쓰는 추천을 설명할 수 있다
- 문턱을 지난 데이터로 정하고 새 데이터로 채점해야 하는 이유를 말할 수 있다
- 도입 판단 다섯 질문을 적용할 수 있다

**시연 순서 팁** 5-2에서 "글자 겹침"과 "좌표"를 번갈아 누르며 DM 광고가 잡히는지 보여 줍니다. 5-4 도우미는 학생 회사 상황으로 직접 고르게 합니다.

**토론 질문** 여러분 회사에 벡터 DB가 필요할까? 다섯 질문으로 답해 보세요.

**퀴즈 정답**

- q51-1. 영화 좌표를 "별점 4점 이상 리뷰"의 평균으로 만든 이유는? → **그 영화를 "좋아한 이유"만 모으려고** — 좋아한 사람들의 말만 모아야 "이 영화를 좋아했다면 이것도"에 맞는 좌표가 됩니다.
- q51-2. 별점 평균순 추천의 약점은? → **모두에게 같은 영화를 추천한다** — 평균은 사람마다 같습니다. 취향(좋아한 이유)을 반영하지 못합니다.
- q52-1. 광고 걸러내기 문턱을 첫 주 글로 정하고 둘째 주로 채점한 이유는? → **채점할 데이터로 문턱을 맞추면 점수가 부풀려지기 때문** — 같은 데이터로 맞추고 채점하면 실제보다 좋아 보입니다. 지난 데이터로 정하고 새 데이터로 재야 공정합니다.
- q52-2. 새 이야기 묶음이 빠르게 커질 때 맞는 대응은? → **묶음 안 글을 읽고 실제 시스템 기록과 맞춰 본다** — SNS 신호는 확인할 곳을 알려 줄 뿐, 확정이 아닙니다.
- q53-1. 챗봇에게 지난 대화를 전부 붙이지 않고 기억 창고를 쓰는 이유는? → **LLM이 한 번에 읽을 수 있는 길이와 비용에 한계가 있어서** — 컨텍스트 창과 비용 때문에, 지금 질문과 가까운 기억만 꺼내 붙입니다.
- q53-2. 이용자가 "그 기억 지워 줘"라고 하면? → **원문과 좌표를 모두 지운다** — 좌표만으로도 내용이 상당 부분 되살아날 수 있어, 원문과 좌표를 함께 지워야 합니다.
- q54-1. 질문 대부분이 주문 조회·재고·정산이라면? → **관계형 DB(표)만으로 충분할 가능성이 크다** — 정확한 값·범위·집계 질문은 표가 가장 잘합니다.
- q54-2. 개인정보가 든 문장을 외부 임베딩 API로 보낼 때의 위험은? → **문장이 회사 밖으로 나간다** — 임베딩을 만들려면 원문을 보내야 합니다. 내부 모델이나 비식별 처리를 검토합니다.

## 6장 · LLM은 찾은 자료를 어떻게 읽나 (특강)

**학습 목표**

- 벡터 DB 검색과 어텐션의 경계를 설명할 수 있다
- Q·K·V와 softmax로 어텐션을 설명할 수 있다
- 근거를 많이 붙일 때의 득실을 말할 수 있다

**시연 순서 팁** 6-1에서 "LLM이 어텐션으로 벡터 DB를 뒤진다"는 오해를 먼저 꺼내고 프롬프트 줄의 경계를 보여 줍니다. 6-3에서 "Q 변환"을 켜 숫자 토큰으로 비율이 옮겨 가는 장면이 핵심입니다. 3D는 끌어서 돌립니다.

**토론 질문** 어텐션과 벡터 검색은 무엇이 같고 무엇이 다른가? 표로 정리해 보세요.

**퀴즈 정답**

- q61-1. RAG에서 LLM이 벡터 DB로부터 실제로 받는 것은? → **조각의 글(프롬프트에 붙은)** — 검색기가 찾은 조각의 글을 프롬프트에 붙여 줍니다. LLM은 그 글을 토큰으로 잘라 다시 자기 좌표로 바꿔 읽습니다.
- q61-2. 어텐션이 쓰이는 곳으로 맞는 것은? → **임베딩 모델 안(넣을 때)과 LLM 안(읽을 때)** — 임베딩 모델과 LLM은 둘 다 트랜스포머라 어텐션을 씁니다. 창고에서 고르는 일은 코사인과 색인이 합니다.
- q62-1. 위치 정보를 더하는 이유는? → **같은 낱말이라도 몇 번째 자리인지 알게 하려고** — 어텐션 자체는 순서를 모릅니다. 위치 좌표를 더해 순서를 좌표에 새깁니다.
- q62-2. 물결 길이 2일 때 자리 1의 위치 값 sin(0.5)는 대략? → **0.48** — sin(0.5) ≈ 0.479.
- q63-1. 점수 2, 1, 0의 softmax 비율로 맞는 것은? → **0.67, 0.24, 0.09** — e² : e¹ : e⁰ = 7.39 : 2.72 : 1, 합 11.11로 나누면 0.665, 0.245, 0.090.
- q63-2. 어텐션과 3장 벡터 검색의 가장 큰 차이는? → **어텐션은 위에서 k개만 고르지 않고 모두에게 비율을 나눠 섞는다** — 둘 다 내적으로 닮음을 재지만, 어텐션은 softmax로 부드럽게 섞고 프롬프트 안에서만 일합니다.
- q64-1. 머리를 여러 개 두는 이유는? → **뜻·순서·글자 같은 여러 관계를 동시에 보려고** — 머리마다 다른 Q·K·V로 다른 관계를 봅니다.
- q64-2. 층을 지날수록 토큰 좌표는? → **주변 토큰의 정보가 점점 더 섞인다** — 층마다 자기 좌표에 어텐션으로 섞어 온 좌표를 더해(잔차 연결) 넘깁니다.
- q65-1. 근거 없이 물었을 때 틀린 "14일"이 나오는 이유(이 실험의 가정)는? → **학습 때 자주 본 말의 점수만 남아서** — 붙인 근거가 없으면 평소 자주 본 말의 점수가 그대로 남습니다. 4장의 환각과 같은 이야기입니다.
- q65-2. 현행·구버전 규정을 둘 다 붙이면? → **3일과 7일이 함께 올라 답이 흔들린다** — 어텐션이 두 근거에 비율을 나누고, 두 숫자의 점수가 함께 오릅니다. 날짜 필터가 필요한 이유입니다.

## 7장 · 좌표와 관계 (특강)

**학습 목표**

- 코사인 문턱을 분포로 정할 수 있다
- 지식 그래프와 GraphRAG의 쓰임을 설명할 수 있다
- 온톨로지로 검색 범위와 데이터 규칙을 정할 수 있다

**시연 순서 팁** 7-1에서 "다른 모델 눈금"을 눌러 같은 0.7의 뜻이 바뀌는 장면, 7-4에서 "하위 개념 포함"을 껐다 켜 0건 → 243건이 되는 장면을 보여 줍니다.

**토론 질문** 우리 부서에서 같은 것을 다르게 부르는 말(다른 이름)을 세 개 찾아보세요.

**퀴즈 정답**

- q71-1. 다른 팀이 쓰는 "코사인 0.7 이상" 문턱을 그대로 가져오면 안 되는 이유는? → **점수의 눈금이 모델과 데이터마다 달라서** — 같은 0.7이라도 모델과 데이터에 따라 뜻이 다릅니다. 우리 데이터의 정답·오답 분포로 다시 정합니다.
- q71-2. 정답 중앙값 0.63, 오답 중앙값 0.30일 때 출발점 문턱 어림값은? → **약 0.47** — (0.63 + 0.30) ÷ 2 ≈ 0.465. 여기서 시작해 정밀도·재현율을 보며 조정합니다.
- q72-1. "프리미엄 → 4K → 25메가비트"를 잇는 것은? → **이름 붙은 관계(지원 화질, 필요 속도)** — 프리미엄과 25메가비트는 뜻이 닮지 않았습니다. 둘을 잇는 것은 관계입니다.
- q72-2. 지식 그래프의 사실 하나를 적는 기본 모양은? → **(주어, 관계, 목적어)** — 삼항(triple)이라고 부르며, RDF의 기본 단위입니다.
- q73-1. GraphRAG에서 좌표(벡터 검색)의 역할은? → **질문과 맞는 그래프의 입구 점을 찾는다** — 질문의 말투와 점 이름이 달라도 좌표로 가까운 점을 입구로 찾습니다. 그다음 선을 따라갑니다.
- q73-2. 따라갈 걸음 수를 늘리면? → **필요한 사실도, 관계없는 사실도 늘어난다** — 빠짐없음과 군더더기의 맞바꿈입니다.
- q74-1. 영화 표에 "긴장감 장르" 값이 없는데도 찾을 수 있게 해 주는 것은? → **온톨로지의 하위 개념 추론** — 공포·스릴러·미스터리·액션이 긴장감 장르의 하위 개념이라는 약속으로 범위를 펼칩니다.
- q74-2. "현행 환불 규정이 둘"이라는 모순을 미리 잡는 것은? → **온톨로지 규칙 검사** — "현행 판은 하나뿐"이라는 약속에 데이터를 비춰 봅니다.
- q75-1. "이번 달 결제 건수는?"에 가장 먼저 꺼낼 도구는? → **표(SQL 집계)** — 정확한 집계는 표가 가장 잘합니다.
- q75-2. "LP-204가 주말에 뜨면 어디에 물어야 빨라?"에 알맞은 조합은? → **좌표로 입구 + 그래프로 여러 걸음** — LP-204 → 결제 문제 → 채팅 상담 → 주말 운영, 여러 걸음 관계입니다.

정답은 하나가 아닙니다. 아래는 `build/check_missions.py`가 자동으로 확인한 조작 중 하나입니다.

**① 리뷰 검색 창구**

**② 고객센터 RAG 창구**

- 날짜 필터 켜기 → 조각 120자, k 2, α 0.5, 문턱 0.55 (15개 이상·지어냄 0·350자 이하)
- 같은 설정에서 구버전 버튼 끄기 → 켜기 (조건이 바뀌어도)
- 날짜 필터 끄고 문턱 0.35 (함정 관찰: 구버전 근거)

**③ SNS 상황실**

- 날짜 14일, 광고 문턱 0.79 (F1 0.95 이상)

- 닮음 문턱 0.44, 알림 기준 2개 (11일째 이전 알림, 다른 알림 1개 이하)

## 자주 나오는 질문

- **"LLM이 어텐션으로 벡터 DB에서 말을 가져오나요?"** 아닙니다. 검색기가 코사인·색인으로 조각을 찾아 글로 붙이고, LLM은 그 글을 어텐션으로 읽습니다(6-1). 다만 임베딩 모델과 LLM 모두 안에 어텐션이 있다는 점에서 "반은 맞다"고 짚어 주세요.
- **"실제 모델로는 결과가 다르지 않나요?"** 다릅니다. 이 시리즈의 숫자는 원리를 보이는 설명용입니다. 실제 도입 전에는 자기 데이터와 질문 묶음으로 다시 재야 한다는 것이 시리즈 전체의 결론입니다.
- **"pgvector와 전용 벡터 DB 중 무엇을 가르치나요?"** 3-5·5-4의 기준(규모, 갱신, 이미 쓰는 DB)으로 판단하게 합니다. 제품 기능은 빠르게 바뀌므로 수업 시점의 공식 문서를 함께 보여 주세요.
